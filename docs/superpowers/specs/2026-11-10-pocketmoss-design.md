# POCKETMOSS · 完整设计文档

> 2.5D 像素风电子宠物养成器 · 手机原生壳 · GBA 像素美学 · AI 分层对话 · 场景制群像

---

## 0. 一句话描述

**POCKETMOSS 是一款手机端 HTML5 游戏——用 GBA 像素美学风格，让玩家在 5 个不同生态场景中照顾一群会真的跟人聊天的元素精灵，收集、养成、散步探索，每只精灵都有独立性格和 AI 对话深度。**

---

## 1. 设计支柱 (Design Pillars)

| # | 支柱 | 含义 |
|---|------|------|
| P1 | **口袋里的微缩世界** | 一个手机 = 5 个完整生态场景，切换即穿梭；每只精灵都有独立空间 |
| P2 | **像素即魔法** | GBA 色板 + 8-bit 字体 + 纯 CSS/div 绘制；2.5D 地板透视强化"立体口袋"感 |
| P3 | **AI 对话是"加分层"而非"必需层"** | 不调用 API 也能玩完整；调用 API 解锁深度陪伴和剧情；成本可控 |
| P4 | **场景即玩法** | 不同元素精灵只能在对应场景发挥最佳状态；散步事件由场景决定 |
| P5 | **群像 > 独奏** | 一次展示多只精灵，观察它们之间的互动本身就是核心乐趣 |

## 2. MDA 分析

### 2.1 Mechanics（机制层）

**核心资源与状态：**

| 系统 | 机制 | 说明 |
|------|------|------|
| 宠物状态 | ❤ 饥饿 / ⚡ 心情 / 💧 清洁 | 每只精灵独立；随时间衰减；离线时间做补偿结算 |
| 场景解锁 | 元素解锁门槛 | 每场景需要对应元素至少孵化 1 只精灵才能进入 |
| 孵化系统 | 蛋 → 随机元素 → 3 种精灵之一 | 同一批蛋中，同元素 3 选 1 |
| 散步事件 | 场景 × 随机事件表 | 每个场景有 8-12 个固定事件 + AI 动态事件 |
| 好感度 | 对话 + 互动累积 | 高好感解锁精灵专属形态（进阶皮肤）和隐藏剧情 |
| 存档 | localStorage + 云端可选 | 宠物全部数据持久化；每日离线衰减补偿有上限 |

**AI 对话分层机制：**

| 层级 | 触发 | 内容 | 成本 |
|------|------|------|------|
| L1 浅对话 | 点击宠物、状态变化 | 根据当前状态 + 性格说一句话（"我饿了~" / "今天好想散步！"） | 低 — 本地预置台词 + 随机组合，**零 API 调用** |
| L2 剧情对话 | 散步时遇到事件 | 精灵根据性格对事件做简短反应（"好可怕…不要去！" / "看起来很有趣！"） | 中 — 本地剧本化选项 + API 润色 |
| L3 深度对话 | 玩家主动发起、关键剧情 | 完整多轮对话，精灵有记忆、有情绪曲线；会对玩家做印象评级 | 高 — 真正的 LLM 调用，有 prompt 成本控制 |

### 2.2 Dynamics（动态层）

**玩家 → 游戏：** 喂食 / 玩耍 / 清洁 / 散步 / 对话 → 改变状态值、触发事件、累积好感度

**游戏 → 玩家：** 状态衰减倒计时 → 紧迫感到来；状态触发 L1 浅对话 → 情感反馈；好感度累积 → 解锁提示；场景内精灵群像变化（多了新成员）→ 成就感

**精灵 ↔ 精灵（群像动态）：** 同场景多只精灵会自动做同步动作（一起呼吸、同步跳、轮流眨眼），高好感精灵之间会触发彩蛋互动（拥抱、分享食物）

**离线动态：** 离开游戏后状态继续按时间衰减，但做每日上限补偿（一次最多补 6 小时），防止长时间不登录数值归零导致挫败感

### 2.3 Aesthetics（美学层）

| 维度 | 决策 |
|------|------|
| 视觉风格 | GBA 像素美学 — 8-bit 字体、低饱和 15-bit 色板、像素化图标 |
| 画面密度 | 场景 + 2.5D 地板透视（等腰梯形 clip-path 模拟近大远小） |
| 主色调 | GBA 经典绿 `#9bbc0f / #8bac0f / #306230 / #0f380f` 作为全局衬线 |
| 场景色调 | 每场景独立色系（见元素场景矩阵） |
| UI 动画 | 像素位移动画（translate 而非 transform scale）、颜色插值走离散步长 |
| 交互反馈 | 点击有像素化粒子爆散、状态变化有数字跳字、AI 对话气泡逐字打字机效果 |
| 字体 | 等宽 monospace 全局统一，模拟 GBA 字体质感 |

## 5. 核心玩法循环

```
[孵化/收集] → [切换场景] → [照顾群像] → [触发事件] → [解锁新内容]
    ↑                                              │
    └──────────── 好感度/等级累积 ←────────────────┘
                      ↓
              解锁进阶形态 / 隐藏剧情
                      ↓
              AI L3 深度对话解锁
```

**日循环：** 每天登录 → 看宠物状态 → 喂食/清洁 → 散步触发事件 → 收集新蛋 → 孵化 → 新精灵加入场景

**周循环：** 累积 3-5 只精灵 → 好感度提升 → 触发专属剧情（AI L3 对话）→ 解锁精灵进阶形态

## 6. 范围分层（Scope Tiers）

### 🔹 MVP — 可玩原型 (Week 1-2)

| 模块 | 内容 | 排除 |
|------|------|------|
| 场景 | 1 个完整场景（Whispering Forest + GBA 绿板） | 4 个其他场景 |
| 宠物 | 3 只精灵（苔藓兽、蘑菇灵、藤叶精），纯 CSS div 绘制 + 基本动画（呼吸眨眼） | 其他 12 只精灵 |
| 状态系统 | ❤⚡💧 三条数值条 + 离线时间衰减补偿 | 好感度系统 |
| 互动 | 喂食/玩耍/清洁（本地数值变化 + L1 台词） | 散步/事件 |
| UI | 方案 C 完整布局（顶部 HUD + 底部 5 按钮） | 场景切换界面 |
| AI | L1 浅对话（本地预置台词 + 状态触发） | L2/L3 对话 |
| 存档 | localStorage 单存档 | 多存档/云同步 |
| 动态效果 | 群像基础站位 + 点击粒子爆散 | 精灵间互动/彩蛋 |

**MVP 完成标志：** 可以打开游戏 → 看到森林场景里 3 只精灵 → 点击按钮互动 → 状态变化 → 精灵说话 → 刷新后数据保留

### 🟡 Phase 2 — 完整玩法 (Week 3-5)

| 模块 | 新增内容 |
|------|---------|
| 场景 | 全部 5 场景 × 独立色调 × 2.5D 地板透视 |
| 宠物 | 全部 15 只精灵 + 独立性格参数 |
| 孵化 | 蛋系统 → 随机元素 → 3 选 1 |
| 散步 | 每场景 8 个固定事件（剧本化） |
| 群像互动 | 多只精灵同步呼吸/眨眼 + 随机彩蛋互动 |
| 好感度系统 | 对话 + 互动累积 → 解锁条件判断 |
| AI L2 | 散步事件时精灵反应（性格驱动） |
| UI | 场景切换 Tab + 精灵图鉴界面 |
| 进阶形态 | 好感度阈值解锁精灵进阶皮肤（换色 + 小 feature 变化） |

### 🟢 Phase 3 — 创新深度 (Week 6+, 可迭代)

| 模块 | 新增内容 |
|------|---------|
| AI L3 深度对话 | 玩家主动发起多轮对话 + 精灵记忆系统 |
| AI 动态事件 | 散步时 AI 实时生成新事件（低成本、限长度） |
| 精灵印象 | 每只精灵对玩家独立的印象值（被冷待会疏远） |
| 隐藏剧情 | 高好感 + 特定场景组合触发专属剧情支线 |
| 成就系统 | 图鉴完成度 / 场景全探索 / 彩蛋发现率 |
| 云端同步 | 可选 Google / Apple 登录 + 存档云同步 |
| 像素 BGM | 每场景 1 首 chiptune 循环 + 事件音效 |
| 天气系统 | 场景内动态天气（云/雨/雪/雷暴）→ 影响精灵行为 |
| 小游戏 | 精灵解锁迷你互动游戏（接食物、打扫房间） |

## 7. 技术栈

| 层 | 选型 | 说明 |
|---|------|------|
| 宿主 | HTML5 + Vanilla JS (ES6+) | 零框架依赖，单页 SPA，直接打开运行 |
| 渲染 | Canvas + 纯 CSS/div 混排 | Canvas 负责 2.5D 场景 + 粒子效果；CSS/div 负责 UI 和精灵占位渲染（MVP）；Phase 2 精灵升级为像素 SVG |
| 状态管理 | 类式模块 + localStorage | PetState / SceneState / GameState 独立类，纯数据无 DOM 引用 |
| 动画 | requestAnimationFrame + CSS keyframes | 精灵呼吸、粒子爆散用 rAF；UI 微动画用 keyframes |
| AI 接入 | fetch + 可配置 API endpoint | `AI_API_URL` + `AI_API_KEY` 在 settings 里配置；不配置则自动降级到 L1 本地台词 |
| 移动端适配 | `100dvh` + `clamp()` + touch events | 解决 iOS Safari 地址栏伸缩和小屏溢出问题；touchstart/touchend 替代 click |

**项目结构（MVP）：**

```
/workspace/
├── index.html          # 单页入口
├── css/
│   └── styles.css      # GBA 色板变量 + 全部 UI 样式 + keyframes
├── js/
│   ├── game.js         # 主入口 + 初始化
│   ├── state.js        # PetState / SceneState / GameState 类
│   ├── storage.js      # localStorage 持久化 + normalize
│   ├── renderer.js     # Canvas 2.5D 场景渲染 + 精灵位置计算
│   ├── sprites.js      # 精灵像素绘制函数（纯 CSS/div 生成）
│   ├── interactions.js # 喂食/玩耍/清洁/对话 触发逻辑
│   ├── ai.js           # AI 分层路由（L1 本地 / L2 剧本 / L3 LLM）
│   ├── scenes.js       # 5 场景数据（色调 / 地板 / 装饰元素）
│   └── config.js       # 全部常量、衰减速率、AI endpoint 等集中配置
└── assets/             # （可选）像素素材 / chiptune BGM
```

## 8. 风险与缓解

| 风险 | 概率 | 影响 | 缓解策略 |
|------|------|------|---------|
| AI API 成本超支 | 中 | 高 | L1 默认开启、L2/L3 设 prompt 长度上限、每精灵每日 L3 有次数上限、未配置 API Key 自动降级 |
| 2.5D 地板透视渲染性能差 | 低 | 中 | Canvas 静态层预渲染 + 仅重绘精灵位置；精灵数量上限每场景 5 只 |
| 长时间离线数值归零 | 中 | 高 | 补偿结算上限 6 小时 + 归零后不删除精灵，只标记"需急救" |
| 移动端地址栏伸缩导致布局抖动 | 中 | 中 | `100dvh` + 固定定位 + `visualViewport` 监听 |
| 精灵像素绘制工作量大 | 高 | 低 | MVP 先用 SVG 路径生成 + 占位；Phase 2 再精修 |

## 9. 关键设计取舍记录

| 决策点 | 最终选择 | 放弃的替代 | 理由 |
|--------|---------|-----------|------|
| 外壳 | 手机原生壳全屏 | GBAsp 物理模拟 | 现代手机沉浸感 + 触摸交互更自然 |
| 视觉 | 像素美学（纯视觉） | 完整 GBAsp 模拟 | 保留怀旧感但不牺牲现代体验 |
| 布局 | 方案 C 全屏 Grid | A 极简 / B 侧栏 | 信息密度最高，群像 + 常驻数值一屏可见 |
| 循环 | 收集探索（孵化→照顾→事件） | 纯养成 / 纯小游戏 | 可持续性更好，内容扩展空间大 |
| 宠物 | 元素精灵（5 元素） | 真实动物 / 奇幻生物 | 与场景天然绑定，世界观统一 |
| AI | 分层（默认离线可用） | 全程 LLM | 成本可控 + 可玩性不依赖 API |
| 展示 | 场景制 + 群像 | 主宠独奏 / 群像同框 | 场景切换 = 世界观穿梭，群像本身是乐趣 |
| 渲染 | 纯 CSS/div + Canvas 混排 | 全 Canvas / 全 DOM | CSS/div 绘制像素精灵直观易改，Canvas 适合 2.5D 场景和粒子 |
